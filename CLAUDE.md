# CLAUDE.md

**«Тотальный Учёт»** (`goigolden88/TotalUchet`) — метаприложение семьи local-first приложений: «Делу Время», «Трапеза», «Дневники», «Злотые», потом «Дача». Читает их срезы итогов (`summary.json` в приватных репозиториях данных) и показывает на одном экране: что было за неделю и месяц и кто из приложений зовёт. Своих записей о жизни не ведёт, сырых данных приложений не читает.

**Стек:** Vite + React + TypeScript (`strict`, `noUncheckedIndexedAccess`), хеш-роутинг, обычный CSS, IndexedDB. Ядро семьи `FamilyCore` — подмодулем в `src/shared/` (Р-02). Бэкенда нет, своей синхронизации нет (Р-02). Сайт — GitHub Pages.

## Документы

Лежат в `docs/` и являются источником истины. Код им подчиняется, а не наоборот.

- `01-Проект.md` — зачем, границы, экраны, соседи
- `02-Архитектура.md` — модель, чтение срезов, показ, структура кода, жёсткие правила
- `03-План.md` — что предстоит
- `04-Журнал.md` — что сделано и где мы сейчас
- `05-Решения.md` — решения **«Р-NN»** и почему так
- `06-Процесс.md` — как ведётся работа, где что живёт, передача в следующую сессию

Договор семьи — форма среза, правила чтения, состав — **не здесь**, а в ядре: `src/shared/docs/02-Архитектура.md`, «Договор семьи», и решения `src/shared/docs/05-Решения.md` (Я-10…Я-22). Здесь на них ссылаются, а не переписывают.

## Как работать

1. В начале сессии прочитай `04-Журнал.md` и `03-План.md` — там текущее состояние и следующий шаг.
2. Сверяйся с `02-Архитектура.md` перед тем, как писать код. Имена и типы берутся оттуда.
3. Отступление от Архитектуры, прежнего решения или договора семьи — вслух до кода. Молча менять нельзя.
4. Сначала план работ, код после подтверждения.
5. Коммить осмысленными порциями. Перед `/clear` дерево чистое и всё запушено.
6. Решение записывается в `05-Решения.md` сразу, в момент выбора. Старые записи не переписываются: отмена — новая запись со ссылкой.
7. В конце сессии — запись в `04-Журнал.md`. Отдельно — «не описано в документах»: это уходит на обсуждение, а не решается на месте.
8. Если документ устарел — скажи, не подстраивайся.

## Правила кода

- **Показываем, а не досчитываем** (Я-15, предварительно): ни серий, ни средних на день, ни сумм между строками и приложениями, ни цвета по оценке, ни вердикта сверх данного хозяином. Форматирование берёт одно значение за раз
- **Читается только `summary.json`** (Я-11, Я-16) — ни файлов хранилищ, ни чужих баз IndexedDB на origin
- **Список приложений и имена репозиториев — записи человека, не код** (Я-16, Я-22). Ни одного имени репозитория, адреса сайта приложения или названия группы в исходниках
- **Ошибка одного приложения не ломает остальные:** у каждого своё состояние чтения словами
- К хранилищу — только через `db` из `src/app/core.ts`; `indexedDB` напрямую — только в `src/shared/core/db.ts`
- Секретов в репозитории нет: токен — в `settings` устройства, в файл-копию не входит
- Логика — чистыми функциями с тестами; экраны проверяет прогон в браузере
- Перед пушем — `npm test`, `npm run typecheck`, сборка и прогон; итог по коду выхода
- Интерфейс и комментарии на русском, имена в коде на английском

## Репозиторий публичный (Р-01)

- **Ни токенов, ни данных, ни примеров из настоящих срезов** — даже названий групп: ключ `time.group.<ключ>` «Делу Время» — нормализованное название группы человека. Тесты — на выдуманных срезах, приложения в них — выдуманные
- **Логи GitHub Actions видны всем:** ни один workflow не печатает содержимое среза, токен или ответ API

## Правила интерфейса

- Текст, в котором может поменяться число или правило, собирается из констант кода, а не пишется цифрами
- Название приложения на экранах — из одного места (своё название, Р-03), не строкой в исходнике
- Изменение, которое видно человеку, идёт в том же коммите со строкой в `src/changes.ts`
- Новые блоки экрана — сворачиваемые (`src/shared/ui/Fold.tsx`), где это уместно: разделы экранов и подгруппы внутри них. Что свёрнуто, помнит устройство

## Для конвейера

Агенты конвейера «Штаб» (`goigolden88/Shtab`) работают здесь без человека: берут issue с меткой `готово`, присылают PR, сливает только человек (Р-30). Правила выше действуют целиком; здесь — только то, что агенту нужно сверх них.

- **Клон:** `git submodule update --init`, затем `npm ci` — в облаке подмодуль сам не скачивается
- **Проверки перед PR:** `npm test`, `npm run build` (в нём `tsc --noEmit`), `npm run smoke` — итог по коду выхода. Те же гоняет CI на каждый PR (Р-30). Нет браузера в окружении — `smoke` не запустится: так и написать в отчёте, решает CI
- **Чужое:** файлы в `src/shared` не правятся; поднимать указатель подмодуля можно — с проверками и строкой в `src/changes.ts`, если изменение видно человеку. Репозитории приложений семьи только читаются
- **Только через `нужно-решение`:** шаг миграции и всё, что меняет хранимые данные (хранилища, индексы, версия схемы); всё, для чего нужна правка ядра или договора семьи; новая npm-зависимость; новое решение Р-NN; правка `.github/`, этого файла и `docs/`
- **Блок «Решение»** в тексте issue (Штаб, Ш-37, Ш-44) — решение владельца, принятое до задачи: перенести его в `docs/05-Решения.md` следующим номером Р-NN, оформлением соседних записей, в том же PR, что и код, — это разрешено, хоть и `docs/`. Шаг миграции — только если блок называет его прямо и он только добавляет (новое хранилище или необязательное поле; старые записи не переписываются)
- **Данные:** репозитории данных семьи не открывать и не клонировать — ни срезов, ни файлов хранилищ; токенов у агента нет и не нужно. Тесты и прогон — на выдуманных срезах (Р-01)
- **Бот:** сообщения в Телеграм агент не шлёт и `npm run bot` не запускает — у бота свои секреты в приватном репозитории человека (Р-23). Сообщение проверяется тестами `src/bot/`
- **Отчёт** — в описании PR, по шаблону Штаба; Журнал и План агент не правит — их ведут сессии человека
- **После слияния** сайт выкатывается сам из `main`, бот берёт код с `main` при следующем запуске (Р-23); проверка — на телефоне, шаги для неё — в отчёте
