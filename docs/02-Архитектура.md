## Стек

- **Vite + React + TypeScript**, `strict` и `noUncheckedIndexedAccess` — как у всей семьи; `tsconfig.json` — `extends` от `src/shared/tsconfig.base.json`
- **HashRouter** — GitHub Pages не отдаёт обычные пути
- **Ядро `FamilyCore` подмодулем в `src/shared/`** (Р-02): `createDb`, `settings`, файл-копия, клиент GitHub, даты, `parseSummary` и типы среза, `Layout`, `Install`, «Что нового», `Report`, работник, каркас стилей, `familyVite`, иконки
- **IndexedDB** через `createDb` ядра. **Своей синхронизации нет** — `createSync` не вызывается (Р-02)
- **GitHub API — только на чтение**, одним fine-grained токеном с «Contents: Read-only» на репозитории данных семьи (Я-16, Р-02)
- Тесты — Vitest с `fake-indexeddb`; экраны — прогоном в браузере (скилл `browser-smoke-cdp`)
- Бэкенда нет. Сайт — `goigolden88.github.io/TotalUchet/`, `base: '/TotalUchet/'`

## Что читаем — договор семьи

Форма среза, путь и правила — **не здесь**: `src/shared/docs/02-Архитектура.md`, «Договор семьи», «Срез итогов»; код — `src/shared/core/summary.ts`. Здесь — только как мы его читаем и показываем. Коротко, что из договора держит этот код:

- `summary.json` в корне репозитория данных приложения; нет файла — **«срез не отдаёт»**, не ошибка (Я-16)
- проверка — `parseSummary` ядра, одна на писателя и читателя (Я-17, Я-20)
- четыре отрезка **на день расчёта `computedOn`**, а не на сегодня: прошлая и идущая неделя, прошлый и идущий месяц (Я-17)
- `through` — у идущего отрезка «по какое число»; `null` — отрезок закончился, **но не заморожен**; свежесть — `computedOn` и `lastEdit` (Я-21)
- пункт «требует внимания» есть — хозяин зовёт; нет — не зовёт, **не «всё сделано»** (Я-21)
- показываем, а не досчитываем (Я-15, предварительно); сопоставление строк соседей — по группе, настройкой человека (Я-19)

## Модель данных

### Общая часть

`Base` — ядра (`src/shared/core/model.ts`): `id`, `updatedAt`, `deleted?`. Свои записи — с `Base`, хотя синхронизации нет: так файл-копия сливается по записи, а синхронизация, если понадобится, добавится без миграции (Р-02, Р-08).

### Приложение семьи — хранилище `apps`

```ts
type App = Base & {
  name: string        // подпись на экранах: «Делу Время»; вписывает человек
  dataRepo: string    // репозиторий данных «владелец/имя»: откуда читать summary.json
  site: string        // адрес сайта приложения со слешем в конце — для ссылок «открыть»
  order: number       // порядок на «Сводке» и в «Семье»
}
```

Список приложений — записи человека, не код (Я-16, Я-22): у друга свои. `id` — ULID.

### Увиденный срез — хранилище `seen` (Р-08)

```ts
type Seen = Base & {
  // id = `${app}:${computedOn}` — не ULID: один срез, прочитанный дважды или на двух
  // устройствах, — одна запись; позднее прочтение того же дня расчёта её перезаписывает
  app: string         // id записи App
  computedOn: DateStr // день расчёта среза — он же в id
  readAt: string      // ISO 8601: когда прочитан
  sha: string         // отпечаток файла в репозитории данных: тот же — не скачивать заново
  summary: Summary    // как пришёл, после parseSummary
}
```

- **Последний увиденный** срез приложения — запись с наибольшим `computedOn`. По нему «Сводка» работает без сети
- **Архив** — все записи: по одной на приложение и день расчёта. Экрана у архива пока нет (Р-08). Числа в нём — «как видели тогда»: прошлое у приложений пересчитывается задним числом (Я-21), архив этого не знает
- Удалённое приложение: записи `seen` остаются — это история

### Настройки устройства — `settings` ядра, не синхронизируются, в файл-копию не входят

| Ключ | Что лежит |
|---|---|
| `readToken` | fine-grained токен только на чтение (Я-16) |
| `title` | своё название приложения (Р-03); нет — «Тотальный Учёт» |

### Раскладка на будущее

`places` в `AppConfig` обязательны и **замораживаются после первого релиза** (Я-09), даже пока синхронизации нет:

| Хранилище | Место |
|---|---|
| `apps` | `apps.json` — одним файлом |
| `seen` | `seen/ГГГГ-ММ.json` — по месяцам, по `computedOn` |

Порядок: пять приложений × день расчёта × несколько килобайт — около 10 МБ в год; месяц — сотни килобайт.

## Конфиг — `src/app/config.ts`

`AppConfig` ядра: `name: 'Тотальный Учёт'`, `dbName: 'totaluchet'` (в договор «Устройство и origin» его вписывает сессия ядра), `schemaVersion: 1`, `stores: ['apps', 'seen']`, `v1Stores` — те же, `indexes` — `seen` по `app`, `places` — таблица выше. Поля `summary` нет: своего среза метаприложение не отдаёт.

## Чтение среза (Р-05)

Для каждого приложения отдельно, параллельно; ошибка одного не трогает остальных. Когда — при открытии «Сводки» и кнопкой «Обновить»; в фоне не читаем.

1. **Нет токена** → «не настроено: нет токена» — одна подсказка на весь экран со ссылкой на «Настройки»
2. **Доступ к репозиторию** — `info()` клиента ядра. `404` → «токен не видит репозиторий `<dataRepo>`: опечатка в имени или токен выдан не на него». Приватный репозиторий без доступа GitHub отдаёт тем же 404, что и несуществующий: поэтому доступ проверяется **до** файла, иначе «нет доступа» выглядело бы как «срез не отдаёт». `401` → «токен не принят». `canWrite: true` → предупреждение в «Настройках»: токен шире, чем «только чтение» (Я-16)
3. **Файл** — голова ветки по умолчанию, дерево, запись `summary.json`. Нет записи → **«срез не отдаёт»** — спокойным текстом, не ошибкой (Я-16)
4. **Тот же `sha`**, что у последнего увиденного, — файл не качаем, срез прежний
5. **Разбор** — `parseSummary`. Не сошлось → «срез не сходится с формой: …» словами ядра; ниже — последний увиденный со своей датой
6. **Запись в `seen`** с `readAt`
7. **Нет связи** → последний увиденный с пометкой «прочитан ДД.ММ ЧЧ:ММ, сейчас нет связи»

Тексты ошибок ядра для 403 и 404 написаны для пишущего («нужен доступ Read and write»), поэтому для читателя тексты — свои, по коду ответа.

## Показ (Р-04, Р-06)

### «Сводка»

1. **«Зовут»** — пункты `attention` последних увиденных срезов, по приложениям в их порядке, внутри — как отдал хозяин. Пункт: подпись, `count`, если не `null`, «за ДД.ММ» по `day`, основание, «открыть» — `site + '#' + link`. Пусто — «приложения сейчас не зовут», не «всё сделано» (Я-21)
2. **Отрезок** — переключатель: **идущая неделя** (по умолчанию), прошлая неделя, прошлый месяц, идущий месяц. Отрезок экрана считается от **сегодня** устройства (`weekPeriod`, `monthPeriod` ядра)
3. **По приложению** — блок в порядке `order`:
   - шапка: имя; «посчитано ДД.ММ · по записям по ДД.ММ» (`computedOn`, `lastEdit`; `null` — «записей нет»)
   - **отрезок среза ищется по концам, а не по месту в списке.** Срезы разных приложений посчитаны в разные дни, и их «прошлая неделя» — разные недели. Неделя — `grain: 'week'` и `from` равен началу недели экрана. Нет — «не известно: срез посчитан ДД.ММ, этой недели в нём нет»
   - идущий отрезок (`through` не `null`) — «идёт, по ДД.ММ». При `null` — ничего: ни «окончательно», ни «заморожено» (Я-21)
   - `metrics` — «не известно» целиком → одна строка словами хозяина
   - строки — **в порядке хозяина**, без сортировки: подпись, значение, основание под ней, всегда видно
4. Приложение без среза — одна строка состояния чтения (выше)

### Значения словами — одно значение за раз

| Значение | Как видно |
|---|---|
| `n` + `minutes` | «5 ч 40 мин» |
| `n` + `count`, `days`, `kcal`, `km` | число и единица словами, склонение — `plural` ядра |
| `n` + `share` | **не решено**: договор не говорит, доля это от 0 до 1 или проценты — вопрос сессии ядра. До ответа — число как есть |
| `money` + `currency` | `Intl.NumberFormat` с кодом валюты; минимальные единицы делятся на 10 в степени числа знаков валюты, а не всегда на 100 |
| `verdict` | «выполнено», «не выполнено», «не ясно» — **без цвета** (Я-15) |
| `unknown` + `text` | «не известно — <text>», приглушённо; код причины не показывается |

### Месяц, который не календарный

Я-12 разрешает приложению «месяц» не календарный, видимый по концам (`periodStartDay` «Злотых»). Пока таких срезов нет, месяц ищется так же, по `from`; не совпало — «не известно» с концами приложения. Правило сопоставления — когда появится первый такой срез, решением.

### «Семья» (Р-07)

По приложению: имя, ссылка на `site`, состояние среза — «отдаёт, посчитан ДД.ММ», «срез не отдаёт», «нет доступа», «не настроено»; подсказка «открой и нажми „Установить“». Здесь же добавить, поправить, переставить, убрать приложение. Отметки «установлено» нет.

### Своё название (Р-03)

Шапка, заголовок вкладки браузера и тексты, называющие приложение, берут имя из одного места — `src/ui/title.ts`: `settings.title` или «Тотальный Учёт». Название в кавычках не склоняется. Манифест — имя при установке — зашит при сборке и за настройкой не следует.

## Структура кода — первое приближение

```
src/
  shared/          FamilyCore — подмодуль, отсюда не правится (Р-02)
  app/
    model.ts       App, Seen, таблица хранилищ, SCHEMA_VERSION, миграции
    config.ts      AppConfig: dbName, хранилища, places
    core.ts        db = createDb(config)
  reading/         без React, с тестами
    read.ts        чтение одного среза: доступ → файл → разбор → состояние словами
    seen.ts        последний увиденный, запись в архив
  view/            без React, с тестами
    periods.ts     отрезок экрана и поиск отрезка среза по концам
    values.ts      значение словами — одно за раз
    attention.ts   «Зовут» по последним срезам
  ui/
    title.ts       своё название (Р-03)
  screens/
    Summary.tsx  Family.tsx  Settings.tsx
  changes.ts  app.tsx  main.tsx  sw.ts  styles.css
scripts/
  smoke.mjs  icons.mjs
```

**Правила, которые соблюдаются жёстко:**

- `reading/` и `view/` без React; экраны сводят их, а не считают
- **Функции, которая берёт несколько показателей и отдаёт новое число, нет** (Я-15). Раскладка по экрану — да, арифметика между строками — нет
- Читается только `SUMMARY_PATH` ядра — ни одного другого пути репозитория данных (Я-11)
- К хранилищу — только через `db` из `app/core.ts`
- **Тесты — на выдуманных срезах:** выдуманные приложения и группы, срез собирается `buildSummary` ядра — например, из `shelfSummary` «Полки» (`src/shared/testing/shelf.ts`). Ни одного настоящего `summary.json` в репозитории (Р-01)

## Версионирование схемы

Механика ядра: `schemaVersion` и `migrations` в конфиге, версия 1 с первого дня, `v1Stores` и `places` заморожены после первого релиза (Я-08, Я-09). Файл-копия — формат ядра; токен в неё не входит.
