### Сессии Claude Code

Запускать из корня `TotalUchet`: история бесед привязана к рабочей папке. Между этапами — `/clear`, `/compact` — для середины этапа. Перед `/clear`: дерево чистое, всё запушено, и по одному Журналу понятно, где мы и что дальше.

### Ядро — подмодулем

- **Клон** — только `git clone --recurse-submodules`; уже склонированное — `git submodule update --init`. Иначе `src/shared` пустой, сборка падает непонятно
- В `deploy.yml` у `actions/checkout` — `submodules: true`
- **В `src/shared` не запускать `npm install`** — появится вторая копия React (Я-02)
- **Обновление ядра** — `git submodule update --remote src/shared`, тесты, сборка, прогон, коммит указателя. Перед пушем `git status` чистый **и в подмодуле**: `git -C src/shared status`
- **Нехватка в ядре или противоречие с договором** — не правка `src/shared`, а слово человеку: это сессия ядра, решение Я-NN. Потом — обновление указателя здесь

### Сессия ядра — что ей отсюда передаётся

Правки договора — формы, состава, правил чтения — решает только сессия `FamilyCore`. Отсюда — список в Журнале, раздел «Для сессии ядра», человек несёт его туда.

## Телеграм-бот: как завести

Сводка недели по понедельникам и месяца 1-го числа — в личный чат (Р-23…Р-29). Код — в этом репозитории; запускает его workflow **приватного** репозитория человека: там `bot.json` и секреты, а логи не видны чужим. На «Настройки» → «Телеграм-бот» ведёт ссылка сюда — заголовок раздела не менять.

### Одной командой

Скрипт `npm run bot:setup` (Р-32) — на своём компьютере, в клоне `TotalUchet` после `npm ci`; нужен [GitHub CLI](https://cli.github.com) `gh` с входом: `gh auth login`, и право класть workflow: `gh auth refresh -s workflow`.

**Руками до неё** — то, для чего у Телеграма и GitHub нет API: шаг 1 (бот у @BotFather) и шаг 3 (токен чтения бота) ручного пути ниже, и «Настройки» → «Телеграм-бот» → «Скачать список для бота» — файл `bot.json`. После — шаг 8, превью на экране блокировки.

**Что она делает.** Спрашивает токен бота и токен чтения — скрытым вводом, символы на экран не выводятся (или берёт из переменных `TELEGRAM_TOKEN`, `READ_TOKEN`), путь к `bot.json`, имя приватного репозитория (по умолчанию `totaluchet-bot`) и часовой пояс (по умолчанию — системный). Затем сама:

- id чата — просит написать боту `/start` и узнаёт его у Телеграма; чат не личный — отказ;
- приватный репозиторий — создаёт или берёт свой с тем же именем; есть, но не приватный — отказ;
- кладёт `bot.json` и `.github/workflows/bot.yml` — из `scripts/bot-workflow.yml`, `cron` — 09:00 по твоему поясу, пересчитан в UTC; у пояса с летним временем предупреждает, что время сдвинется на час; восточнее +09:00 — отказ: тогда только ручной путь;
- секреты `READ_TOKEN`, `TELEGRAM_TOKEN`, `TELEGRAM_CHAT` и переменную `TZ`;
- пробный запуск за прошлую неделю и ссылка на прогон: через минуту — сообщение в Телеграме.

Токены не печатаются и на диск не пишутся. `npm run bot:setup -- --dry-run` — только спросить и показать план по шагам: в сеть не ходит, ничего не создаёт.

**Повторный запуск** — когда поменял приложения в «Семье» (новый `bot.json`) или продлил токен чтения: те же ответы, тот же репозиторий — файлы и секреты обновятся, второго репозитория не будет.

### Руками — запасной путь

1. **Бот.** В Телеграме — @BotFather → `/newbot`: имя, адрес бота. Токен, который он выдаст, — секрет `TELEGRAM_TOKEN`. Там же `/setjoingroups` → бот → **Disable**: в группу его не добавить (Р-25)
2. **Id чата.** Напиши своему боту `/start`. В браузере открой адрес `https://api.telegram.org/bot` + токен бота + `/getUpdates` — слитно, без пробелов, скобок и слеша между `bot` и токеном: `https://api.telegram.org/bot123456789:AAHf…/getUpdates`. В ответе — `"chat":{"id":<число>,…,"type":"private"}`; число — секрет `TELEGRAM_CHAT`. `404` — токен в адресе не тот: лишний символ или не целиком. `"result":[]` — напиши боту `/start` ещё раз и обнови страницу. Токен побывал в адресной строке — удали этот адрес из истории браузера. Без токена в адресе: @userinfobot присылает твой id — у личного чата с ботом он тот же
3. **Токен чтения бота** (Я-34) — `github.com/settings/personal-access-tokens/new`: имя «бот», Repository access — Only select repositories — репозитории данных приложений семьи, Permissions — Contents: **Read-only**; срок — **тот же день**, что у токена чтения «Тотального Учёта». Секрет `READ_TOKEN`. Копию вне GitHub не хранить
4. **Приватный репозиторий** — любое имя, Private. «Настройки» метаприложения → «Телеграм-бот» → «Скачать список для бота»; в репозитории — Add file → Upload files → `bot.json` в корень
5. **Секреты** — Settings → Secrets and variables → Actions → New repository secret: `READ_TOKEN`, `TELEGRAM_TOKEN`, `TELEGRAM_CHAT`. На вкладке Variables — `TZ`, свой часовой пояс, например `Asia/Yekaterinburg`: от него «сегодня» бота
6. **Workflow** — в приватном репозитории: Code → Add file → Create new file; имя файла — `.github/workflows/bot.yml` (на `/` GitHub сам заводит папки); в поле ниже — образец `scripts/bot-workflow.yml` этого репозитория целиком; Commit changes. При +05:00 править нечего. Другой пояс: время в `cron` — UTC, 09:00 по +05:00 — это `0 4`; поправь часы в обеих строках `cron` и в условии `BOT_PERIOD`
7. **Проверка** — Actions → «Телеграм-бот» → Run workflow → отрезок. Через минуту — сообщение в Телеграме. В логе — только «Бот: отправлено частей: N» или причина словами
8. **Превью на экране блокировки** показывает начало сообщения — дни болезни, названия групп. Скрыть — настройкой Телеграма: Настройки → Уведомления и звуки → Личные чаты → «Показывать текст» выключить

**Дальше:**

- поменял приложения в «Семье» — снова «Скачать список для бота» и повторный `npm run bot:setup`; руками — Upload поверх старого `bot.json`
- продление — в один день с токеном чтения метаприложения: у GitHub — Regenerate, новое значение — повторным `npm run bot:setup` или руками в секрет `READ_TOKEN`. За 30 дней бот сам напишет в сообщении, что токен скоро истекает (Р-29)
- бот упал до Телеграма — неверный токен бота, чат не личный, нет сети — GitHub пришлёт письмо об упавшем workflow
- утёк токен бота — @BotFather → `/revoke`, новый — в `TELEGRAM_TOKEN`

**Образец `.github/workflows/bot.yml`** — файл [`scripts/bot-workflow.yml`](../scripts/bot-workflow.yml), под +05:00; один источник и для команды, и для ручного пути (Р-32).

## Разделение работы

**Claude Code — и «что строить», и «как».** Он видит настоящие файлы ядра и приложений и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой.** Из чата сюда приходят готовые куски markdown и список того, что переделать в коде. Настоящие срезы в чат не носить.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test`, `npm run typecheck`, сборка, прогон** — итог по коду выхода, а не grep'ом по выводу
- **Видимое изменение — строка в `src/changes.ts`** в том же коммите
- **План содержит только предстоящее**
- **Правки файлов с кириллицей** — инструментом правки или скриптом-файлом из папки сессии, не heredoc Bash: он съедает `\n` и `\` (опыт «Трапезы» и ядра)
- **Чужие репозитории — только `git show`**, не файлы с диска: рабочие копии в CRLF врут
