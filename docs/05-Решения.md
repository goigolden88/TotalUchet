### Р-01 · Репозиторий кода публичный; ни токенов, ни данных, ни примеров из настоящих срезов, ни содержимого срезов в логах
24.09.2026

Повод: вопрос человека в первой сессии — верно ли, что репозиторий публичный, или сделать приватным.

**Решено.** `goigolden88/TotalUchet` остаётся публичным, как вся семья. В нём никогда не бывает токенов, настоящих срезов и их кусков — **в том числе названий групп**: ключ `time.group.<ключ>` «Делу Время» — нормализованное название группы человека (Р-87 «Делу Время»). Тесты — на выдуманных срезах. Ни один workflow не печатает содержимое среза, токен или ответ API: логи Actions публичного репозитория видны всем.

Выбор человека, рекомендация.

**Почему.** GitHub Pages для приватного репозитория — только на платном тарифе. А приватность кода почти ничего не даёт: сайт на Pages открыт всем, собранный JS видит любой. Секретов в коде нет по определению (Я-16: токен — в `settings` устройства). Ядро `FamilyCore` публичное и подключается подмодулем без токена (Р-46, Р-50 «Трапезы») — у нас так же.

Отвергнуто: **приватный репозиторий** — платный Pages ради того, что и так видно на сайте.

**Цена.** Дисциплина вместо замка: выдуманные данные в тестах и документах, осторожность с логами. Телеграм-боту (Этап 4) это не подходит — ему нужен приватный репозиторий или логи без данных (План).

### Р-02 · Ядро — подмодулем; своей синхронизации нет; свои записи — с `Base`; один токен только на чтение
24.09.2026

Повод: стартовый промпт, развилка 1 — берёт ли метаприложение ядро (рекомендация сессии ядра — да) и нужна ли ему синхронизация.

**Решено.**

- **`FamilyCore` — подмодулем в `src/shared/`**, как у приложений семьи. Берём `parseSummary` и типы среза, даты, клиент GitHub, `createDb` с `settings` и файлом-копией, `Layout`, `Install`, «Что нового», `Report`, работник, каркас стилей, `familyVite`, иконки. `dbName` — `totaluchet`; в договор его вписывает сессия ядра
- **Своей синхронизации нет** — `createSync` не вызывается
- **Свои записи — список приложений и архив срезов — хранилищами с `Base`,** хотя синхронизации нет: файл-копия сливается по записи, а синхронизация, если понадобится, добавится без миграции. `places` выбраны сразу и замораживаются (Я-09)
- **Токен один:** fine-grained, «Contents: Read-only», на репозитории данных семьи (Я-16). Новое приложение — правкой списка репозиториев того же токена, не новым токеном. Токен в `settings` устройства, в файл-копию не входит

Выбор человека, рекомендация.

**Почему.** Всё нужное уже есть в ядре и проверено четырьмя приложениями; копия — ровно та беда, из которой ядро родилось (Р-45 «Трапезы»). Синхронизация своих записей требует права записи в свой репозиторий данных. **У fine-grained токена один набор прав на все выбранные репозитории:** токен с записью в свой репозиторий писал бы и в репозитории всех приложений — это нарушает «только на чтение» Я-16. Значит, синхронизация — это второй токен. Своих записей мало: список из пяти приложений переносится файлом.

Отвергнуто:
- **без ядра** — копия механики, форма среза без общей проверки;
- **синхронизация сразу** — второй токен ради пяти строк списка.

**Цена.**

1. Список приложений вводится на каждом устройстве или переносится файлом-копией.
2. Поля импорта `AppConfig` ядра обязательны, а импорта здесь нет — заглушки, вопрос сессии ядра.
3. Правка ядра под метаприложение — только сессией ядра и только если она осмысленна для любого приложения семьи.

### Р-04 · Главный экран — «Сводка»: отрезок переключателем, по умолчанию идущая неделя; отрезок среза ищется по концам; строки — в порядке хозяина
24.09.2026

Повод: стартовый промпт, развилка 2 — что на первом экране, порядок, как видны свежесть, неокончательность и «не известно». Человек: «актуально, конечно, идущая, но и прошлая 100% где-то должна быть».

**Решено.**

- **Переключатель отрезка:** идущая неделя — по умолчанию, прошлая неделя, прошлый месяц, идущий месяц. Экран один на все четыре
- **Приложения** — в порядке, который задал человек в «Семье». **Строки** — в порядке, в котором их отдал хозяин; не сортируем: сортировка по числу — уже оценка
- **Отрезок среза ищется по концам, а не по месту в списке.** Отрезки среза считаются от его `computedOn`: срезы, посчитанные в разные дни, называют «прошлой неделей» разные недели. Нет нужной недели — «не известно: срез посчитан ДД.ММ, этой недели в нём нет»
- **Свежесть** — в шапке каждого приложения: «посчитано ДД.ММ · по записям по ДД.ММ». **Неокончательность** — «идёт, по ДД.ММ» у отрезка с `through`; при `null` — ничего (Я-21)
- **Основание** — под каждой строкой, всегда видно. **«Не известно»** — словами хозяина, приглушённо. **Вердикт** — словами, без цвета (Я-15)
- **Сопоставления групп соседей (Я-19) на первом экране нет** — пока срез отдаёт одно приложение, сопоставлять нечего. Этап 3

Выбор человека, рекомендация. Рекомендация по умолчанию была «прошлая неделя» — человек выбрал идущую.

**Почему.** Идущая неделя — то, про что вопрос «как дела» чаще всего; прошлая — одним тапом. Поиск по концам — единственное, что не врёт при срезах разной свежести. Порядок хозяина и основание всегда — продолжение Я-15 и правила семьи «число — вместе с основанием».

Отвергнуто:
- **отрезок по месту в списке** — неделя одного приложения рядом с другой неделей другого;
- **отдельные экраны «Неделя» и «Месяц»** — две копии одного показа;
- **основание по тапу** — число без основания на экране.

**Цена.** Идущая неделя в понедельник почти пуста — у многих строк «не известно» или ноль. Срез, посчитанный на прошлой неделе, на идущей неделе даёт только «не известно».

### Р-05 · Чтение среза: сначала доступ, потом файл; состояние словами у каждого приложения; без сети — последний увиденный
24.09.2026

Повод: развилки 1–2 — как читается `summary.json` и что видно, когда не вышло.

**Решено.** Порядок и тексты — `02-Архитектура`, «Чтение среза». Главное:

- **Доступ проверяется до файла.** Приватный репозиторий без доступа GitHub отдаёт тем же 404, что и несуществующий. Иначе «нет доступа» выглядело бы как «срез не отдаёт»
- **Нет `summary.json` — «срез не отдаёт»,** спокойным текстом (Я-16)
- **Ошибка одного приложения не трогает остальные**
- **Без сети и при кривом срезе** — последний увиденный со своей датой прочтения
- Читаем при открытии «Сводки» и кнопкой «Обновить»; в фоне — нет
- **Токен с правом записи** — предупреждение в «Настройках» (`canWrite` из `info()` ядра)

Рекомендация, человек согласился со всеми развилками.

**Почему.** Каждое состояние чтения — своё действие человека: нет токена — вписать; нет доступа — поправить токен или имя; срез не отдаёт — дело приложения. Одно «ошибка» их не различит.

**Цена.** На каждое приложение — запросы доступа, головы, дерева и, если срез новый, файла. Лимит токена — 5000 в час, в семье это не заметно.

### Р-08 · Увиденные срезы — архивом на устройстве, по одному на приложение и день расчёта; экрана и синхронизации пока нет
24.09.2026

Повод: развилка 5 — история увиденных срезов: нужна ли и где (Я-17: в срезе её нет; «что видело, метаприложение запоминает само»). Человек: «с Б согласен, но может и В — хочется где-то видеть динамику для аналитики».

**Решено.**

- **Каждый новый срез ложится в хранилище `seen`** — по одной записи на приложение и день расчёта; позднее прочтение того же дня перезаписывает. Последний из них — ещё и то, что видно без сети (Р-05)
- **`id` — из приложения и `computedOn`, а не ULID.** Два устройства, прочитав один срез, дают одну запись — архив потом сливается без повторов
- **Экрана у архива пока нет**
- **Синхронизация архива** между устройствами — не сейчас, но без миграции: записи с `Base`, `places` — `seen/ГГГГ-ММ.json` — выбраны сразу (Р-02). Цена её — второй токен с записью в свой репозиторий данных
- **Экран динамики** — когда архив накопит месяцы. Это вопрос к Я-15, который принят предварительно: ряд значений по неделям — уже почти «серия». Решает сессия ядра вместе с пересмотром Я-15, до экрана

Выбор человека, рекомендация.

**Почему.** В срезе только две недели и два месяца. Если не копить сейчас, через полгода, когда дойдёт до динамики и аналитики связей (Я-10), взять прошлое будет неоткуда. Копить дёшево: около 10 МБ в год. Синхронизировать сейчас — второй токен ради архива, у которого ещё нет экрана.

Отвергнуто:
- **только последний срез** — прошлое теряется безвозвратно;
- **архив с синхронизацией сразу** — второй токен до первого читателя архива.

**Цена.**

1. Архив живёт в одном браузере; у установленного приложения на iPhone хранилище своё, отдельное от вкладки. Страховка — файл-копия.
2. Числа в архиве — «как видели тогда»: прошлое у приложений пересчитывается задним числом (Я-21), архив этого не знает.
3. Архив копится только тогда, когда приложение открывают: дни без открытия — дыры.

### Р-11 · Уточнения чтения: `canWrite` — ещё и строкой на «Сводке»; тот же `sha` — новый `readAt`
25.09.2026

Повод: план Этапа 1, чтение по Р-05.

**Решено.**

- **Предупреждение «токен шире, чем чтение»** — не только в «Настройках» (Р-05), но и одной строкой на «Сводке» со ссылкой в «Настройки». Чтение и так спрашивает `info()` и знает `canWrite`
- **Тот же `sha`, что у последнего увиденного,** — файл не качается, но у последнего увиденного обновляется `readAt`: это время последней проверки, что срез прежний. «Прочитан ДД.ММ ЧЧ:ММ» без сети показывает её, а не первое прочтение

Рекомендация, человек согласился.

**Почему.** Кнопку проверки доступа в «Настройках» можно не нажать ни разу, а токен с записью — главный риск Я-16. Без нового `readAt` срез без сети выглядел бы старее, чем он есть.

**Цена.** Одна запись в базу на приложение при каждом открытии «Сводки»; `updatedAt` записи `seen` двигается от проверки, а не от нового среза.

### Р-12 · Предупреждения «токен шире, чем чтение» нет: GitHub не сообщает права fine-grained токена. Отменяет предупреждение `canWrite` Р-05 и Р-11, п. 1
25.09.2026

Повод: проверка Этапа 1 на настоящем срезе. Человек выпустил токен с Contents: Read-only (скрин настроек токена), а «Сводка» показала «токен шире, чем чтение».

**Как было.** `canWrite` из `info()` ядра — это `permissions.push` ответа GitHub на репозиторий. Для fine-grained токена там, по всему видно, права аккаунта на репозиторий, а не права токена: у владельца — всегда `true`. Предупреждение горело бы у каждого, кто читает свои репозитории. На настоящем GitHub другое объяснение не проверялось; токен на скрине — Read-only.

**Решено.**

- Предупреждения нет ни на «Сводке», ни в «Настройках»; `canWrite` метаприложение не читает
- «Проверить доступ» показывает полное имя репозитория и строку: права токена GitHub не сообщает, Read-only выбирается при выпуске
- Сессии ядра — пункт: комментарий `RepoInfo.canWrite` («есть ли у токена право писать») для fine-grained токенов неверен; «Проверить доступ» у приложений, вероятно, говорит то же неверное
- Р-11, п. 2 — новый `readAt` при том же `sha` — в силе

Рекомендация, человек согласился.

**Почему.** Предупреждение, которое горит всегда, хуже, чем никакого: его перестают читать, и настоящая ошибка тонет.

Отвергнуто: **проверка пробной записью** (неверный запрос на запись: 403 — прав нет, 422 — есть) — у метаприложения не должно быть ни одного пути к записи, даже для проверки (Я-16, Р-09).

**Цена.** Токен с правом записи метаприложение не заметит: держит только выпуск по шагам (Contents: Read-only) — дисциплина человека.

### Р-14 · Ссылки на приложения — как есть, новой вкладкой: открывается установленное приложение или вкладка браузера — оба годятся
