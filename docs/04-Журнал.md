**Вопрос человека: можно ли обойтись одним токеном на всю семью** — ответ сессии, не решение (решает человек и сессия ядра):

- метаприложению токен и так один (Р-02)
- приложениям сейчас — по токену с записью в свой репозиторий на каждом устройстве. **Без переработки кода** можно выпустить один fine-grained токен «семья» с «Read and write» на все репозитории данных и вписать его во все четыре приложения: каждое проверяет только свой репозиторий. Итого два токена — «семья» и чтение для метаприложения — вместо пяти
- **Один на всё** — только если дать метаприложению запись: нарушает Я-16; ошибка метаприложения перестаёт быть безопасной для данных. Не советую
- Цена общего токена: истёк или отозван — встают все приложения разом; утечка — запись во все репозитории. Смягчает то, что граница и сейчас держится правилом, а не браузером: все приложения на одном origin, и скрипт любого из них технически может открыть базу соседа с его токеном
- **Вписать токен один раз на устройство для всех приложений** — правка ядра: общее хранилище на origin. Не переработка, но договор («Устройство и origin»). Вопрос сессии ядра
- **Один репозиторий данных на всех** — переработка, отвергнута Я-16

**Человек выбрал первый путь: токен «семья» с записью для приложений и отдельный токен чтения для метаприложения.** Перепроверено по коду ядра (`core/sync.ts`, `core/layout.ts`):

- *Плюсы:* выпуск и продление — один раз, срок жизни — одна дата; новое приложение, в том числе «Дача», — правкой списка репозиториев того же токена; код не меняется
- *Минус, которого при отдельных токенах нет:* **перепутанный репозиторий данных.** Сейчас приложение с чужим именем репозитория получает 404 и стоит. С общим токеном доступ есть, а `meta.json` хранит только `schemaVersion` — чьи это данные, `parseMeta` не проверяет. Если схема соседа не новее, проход отправит в чужой репозиторий свои файлы хранилищ, `meta.json` со своей версией и `summary.json` поверх соседского. Итог: срез соседа подменён до его следующего прохода; сосед может остановиться на «обнови приложение»; при совпадении имён хранилищ сосед вольёт чужие записи как свои
- *Минусы общие:* утечка — запись во все репозитории; истёк или отозван — встают все разом (ядро предупреждает за 30 дней, `WARN_DAYS`, в каждом приложении)
- *Смягчения:* **токен «семья» — свой на каждом устройстве**, как токен чтения по Я-16: потерянный телефон отзывается один. Имя репозитория сверять кнопкой «Проверить доступ» — она показывает полное имя. **В ядре — защита от чужого репозитория** (список для ядра, п. 6); переходить на общий токен лучше после неё
